Greed is good. General Runtime for Editing, Extending and Delegating.

Greed is an editor you can change while it runs. Edit the Helix way, the Vim way or without modes. Around your files: shells, terminals, tiled and floating panes, notes whose code runs, and agents. In a terminal or its own window, here or on the machine where the work runs.

A small Rust core does what needs speed. Keys, modes, commands, pickers, themes and the agents are Luau plugins you can read, change or replace.

Get started Write a plugin 

$ greed src/main.rs          # in this terminal
$ greed --gui                # the same session in a window drawn on the GPU
:detach                      # leave it running: files, undo, servers, shells
$ greed attach               # and come back to it, from either

Three ways to edit, all first class

Pick the one your hands know. Each style has its own modes and keys, and they share the rest: commands, the leader menu, pickers and every plugin. :style switches while it runs.

Editing styles

Helix

Select, then act.

% s todo enter c done

Every todo in the file, changed at once.

Vim

Say what, then where.

:%s/todo/done/g

The changes show as you type, before it runs.

VS Code

No modes, the keys you know.

ctrl-d ctrl-d done

The next matches, one more each time.

Here, or where the work runs

The editor is a session you attach to, from a terminal or from its own window. Run it on the machine with the code and the builds, and look at it from your laptop: files, shells, terminals, language servers and agents all run over there, while your keys, your theme and your config come with you. Close the lid, and attach again later to everything as you left it.

A shell that keeps its output

Each command becomes a block you can search, fold, filter and run again. $3 is block 3's output. Tables from kubectl, docker or ps filter and sort in place, a watch marks what changed, and the rows are things to act on: a pod's logs, a file, a process. When you want your own shell, a terminal pane runs whatever you like.

Notes whose code runs

A fenced block in Markdown runs when you ask: sh, python, luau in the editor itself, http requests and more. Its output is saved under it, so the file reads well anywhere and a diff shows what changed. Name a block and feed its result to the next one, and a page becomes a small pipeline. Notes have links, todos and an agenda, all in plain files.

Runnable blocks · Notes

```python id=primes
primes = [n for n in range(2, 30)
          if all(n % d for d in range(2, n))]
print(*primes)
```

Agents, as clients and inside

Claude Code, Gemini, Codex or Greed's own agent with the model of your choice run in a pane next to your work. Outside agents connect over MCP, greed ctl and Claude Code's /ide. They see your unsaved changes and selections, and propose edits you review in the buffer. Ask one for a command or a setting and it can write you a plugin, which Greed type checks and tests before you approve it.

Plugins all the way down

What you see comes from Luau plugins written against the same typed API yours use. Each declares what it may touch (files, programs, the network), runs within a time budget, and takes everything it added with it when unloaded.

Terminal or window

The window draws on the GPU, with ligatures, images, PDFs, prose in a proportional font and Markdown shown as a document. The terminal gets the same session and the same theme.

A plugin is a folder

This one adds a command and binds it to the leader's U (space U, or ctrl-space U in the VS Code style). Put it in ~/.config/greed/plugins/upper/, or run greed new upper there to get one with a test. greed test upper runs its tests in a headless editor.

Writing plugins · The Luau API

local greed = require("@greed")

greed.command({
	name = "upper",
	doc = "Upper-case the selections",
	run = function(ctx)
		ctx.buffer:edit(function(e)
			for _, r in ctx.view:selection().ranges do
				local from, to = math.min(r.anchor, r.head), math.max(r.anchor, r.head)
				e:replace(from, to, string.upper(ctx.buffer:slice(from, to)))
			end
		end)
	end,
})

greed.keymap.bind({ layer = "leader" }, { U = "upper" })

Try it

Greed builds with a recent stable Rust and cmake, on Linux and macOS:

$ git clone https://github.com/johnae/greed && cd greed
$ cargo build --release
$ ./target/release/greed README.md

To install it, cargo install --path crates/greed-editor, or with Nix, nix-build. The default plugins are built into the binary, so it runs from anywhere. The first start asks how you like to edit and which theme you want, and writes a config with settings to try.

Greed is early and changes often.
