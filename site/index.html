Greed is good. Get, Reflect, Eval, Edit, Delegate.

Your editor, your shells, your terminals and your agents, in one session that keeps running. Leave it and come back, from this machine or another over ssh, in a terminal or a window. Everything in it is text, so one editor runs through all of it, the Helix way, the Vim way or without modes.

In spirit it's closest to Emacs: an environment you shape as you run it. Underneath is a small Rust core with tree-sitter and language servers built in. On top, everything you see is a plugin in Luau, Lua with gradual types, that you can read, change or replace, and each one can only do what you allowed it.

Get started Write a plugin 

$ greed src/main.rs          # in this terminal
$ greed --gui                # the same session in a window drawn on the GPU
:detach                      # leave it running: files, undo, servers, shells
$ greed attach               # and come back to it, from either

Three ways to edit, all first class

Pick the one your hands know. Each style has its own modes and keys, and they share the rest: commands, the leader menu, pickers and every plugin. :style switches while it runs.

Editing styles

Helix

Select, then act.

% s todo enter c done

Every todo in the file, changed at once.

Vim

Say what, then where.

:%s/todo/done/g

The changes show as you type, before it runs.

VS Code

No modes, the keys you know.

ctrl-d ctrl-d done

The next matches, one more each time.

Here, or where the work runs

The editor is a session you attach to, from a terminal or from its own window. Run it on the machine with the code and the builds, and look at it from your laptop: files, shells, terminals, language servers and agents all run over there, while your keys, your theme and your config come with you. Close the lid, and attach again later to everything as you left it.

Panes, tabs and floats

Split the screen yourself, or let a layout do it: main-stack, columns, spiral or your own in Luau. Float any pane above the rest, and lay the floats out freely, tiled, cascaded or one at a time. The keys follow zellij and work everywhere, even while you type into a terminal.

Panes and their keys

A shell that keeps its output

Each command becomes a block you can search, fold, filter and run again. Tables from kubectl, docker or ps go straight into a stage, as in kubectl get pods | where STATUS != Running, and $1 | chart RESTARTS takes block 1's output again without running it. A watch marks what changed, and the rows are things to act on: a pod's logs, a file, a process. When you want your own shell, a terminal pane runs whatever you like.

The shell

Charts and live boards

Add | chart to a command and its numbers become bars or lines; in a watch the lines move. Keep the commands you look at every day on a board, a Markdown file of live cards laid out in a grid: load, memory, the pods that keep restarting, a Prometheus query.

Charts · Boards

Notes whose code runs

A fenced block in Markdown runs when you ask: shell in the Greed shell, with its tables and charts, python, luau in the editor itself, http requests and more. Its output is saved under it, so the file reads well anywhere and a diff shows what changed; with every=5 it keeps up as it goes. Name a block and feed its result to the next one, and a page becomes a small pipeline. Notes have links, todos and an agenda, all in plain files.

Runnable blocks · Notes

Documents that work things out

A Markdown file can hold fields, formulas and tables whose columns are worked out row by row, with a chart under the table. Change a number and everything that depends on it follows as you type. Data blocks read tables live from CSV, SQLite or PostgreSQL. The file stays plain Markdown that reads well on GitHub.

Live values · Data blocks

Agents, as clients and inside

Claude Code, Gemini, Codex or Greed's own agent with the model of your choice run in a pane next to your work. Outside agents connect over MCP, greed ctl and Claude Code's /ide. They see your unsaved changes and selections, and propose edits you review in the buffer. Several can work at once, each in a workspace of its own whose changes you review and bring in when it's done. Ask one for a command or a setting and it can write you a plugin, which Greed type checks and tests before you approve it.

Agents

Plugins all the way down

What you see comes from Luau plugins written against the same typed API yours use. Each declares what it may touch (files, programs, the network), runs within a time budget, and takes everything it added with it when unloaded.

Terminal or window

The window draws on the GPU, with ligatures, images, PDFs, prose in a proportional font and Markdown shown as a document. The terminal gets the same session and the same theme.

A plugin is a folder

This one adds a command and binds it to the leader's U (space U, or ctrl-space U in the VS Code style). Put it in ~/.config/greed/plugins/upper/, or run greed new upper there to get one with a test. greed test upper runs its tests in a headless editor.

Writing plugins · The Luau API

local greed = require("@greed")

greed.command({
	name = "upper",
	doc = "Upper-case the selections",
	run = function(ctx)
		ctx.buffer:edit(function(e)
			for _, r in ctx.view:selection().ranges do
				local from, to = math.min(r.anchor, r.head), math.max(r.anchor, r.head)
				e:replace(from, to, string.upper(ctx.buffer:slice(from, to)))
			end
		end)
	end,
})

greed.keymap.bind({ layer = "leader" }, { U = "upper" })

Try it

Download the latest Greed: one binary with the terminal and the window, or Greed.app on a Mac, signed and notarized by Apple.

macOS app Linux x86_64 Linux arm64

The releases page has the rest: the macOS binary for the terminal, and a static build of the terminal side for servers and any Linux. On Linux, unpack it into ~/.local:

$ tar -xzf greed-*-linux-x86_64.tar.gz -C ~/.local --strip-components=1
$ greed --gui README.md

With Homebrew, on macOS or Linux:

$ brew install johnae/greed/greed             # the greed command
$ brew install --cask johnae/greed/greed-app  # Greed.app, on macOS

On NixOS, nix run github:johnae/greed, downloaded from greed.cachix.org. For servers there's a static build of the terminal side that runs on any Linux. The default plugins are built into the binary, and the first start asks how you like to edit and which theme you want, and writes a config with settings to try. Then :tutor teaches your style's keys, with lines to practise on, and shows you around.

Greed is early and changes often.
